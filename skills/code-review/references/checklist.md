# 审查清单 — Code Review Checklist

按审查顺序逐一核对。

## □ 数学逻辑 (Math Logic)

- [ ] 公式符号与原始数学定义一致（正负号、指数位置）
- [ ] 似然函数方向正确（最小化负对数似然 vs 最大化似然）
- [ ] 约束条件被正确编码（变换空间、投影、罚函数）
- [ ] KKT 条件检查正确（梯度方向、Lagrange 乘子）
- [ ] 年化/日化因子正确（252 交易日 vs 365 自然日）
- [ ] 百分比 vs 小数一致（0.05 还是 5）

## □ 数据流 (Data Flow)

- [ ] 数据提取路径有效（文件存在、列索引正确）
- [ ] 占位符/缺失值有回退（`------` → 备选方案）
- [ ] 多源数据日期对齐正确（日期交集 vs 并集）
- [ ] 单位换算一致（亿元→元，万股→股）
- [ ] 编码问题（utf-8 vs gbk, 中文字符）

## □ 边界条件 (Edge Cases)

- [ ] 空输入不会崩（空列表、空数组、None）
- [ ] 单元素输入处理（N=1, T=1）
- [ ] 除零保护（分母加 epsilon）
- [ ] log 负数保护（参数 clamp 到正值）
- [ ] sqrt 负数保护（参数 clamp 到 ≥0）
- [ ] 矩阵奇异处理（shrinkage、正则化）
- [ ] 迭代不收敛回退（BFGS 崩了回到网格搜索结果）

## □ 性能 (Performance)

- [ ] 嵌套循环是否必要（能否向量化）
- [ ] 文件 I/O 是否缓存（每次调用都读全量报告？）
- [ ] 重复计算（同一协方差矩阵算多次）
- [ ] 是否过早优化（n<100 时 O(n³) 也无所谓）

## □ 可维护性 (Maintainability)

- [ ] 异常粒度（裸 `except:` 会吞掉什么？）
- [ ] 关键中间值是否打日志（方便事后回溯）
- [ ] 路径硬编码 vs 参数化
- [ ] 函数职责是否单一
- [ ] import 层级正确（相对 vs 绝对）
